# Джеб: сначала границы попытки, затем оценка

Этот отчёт фиксирует первый этап. Следующее расширение на кросс и боковой описано
в [PUNCH-CAPTURE.md](PUNCH-CAPTURE.md); общая реализация теперь в `PunchCapture`,
а `JabCapture` сохранён как совместимая обёртка. Результаты джеба не изменились.

30 сентября 2026. Изменения ограничены захватом джеба, понятностью сообщений и
ожиданием его завершения. Баллы, веса, показатели техники и пороги надёжности
оценки не настраивались. Кросс и боковой используют прежний поток.

## Что установлено

1. В ручных интервалах 14 попыток исходного `jeb10times.mov` проверено 422
   сохранённых кадра. Левая ударная кисть и локоть проходят проверку видимости
   во всех этих кадрах. Правая кисть не проходит её в 102 кадрах, правый локоть —
   в 142. Выхода этих точек за изображение нет; причина — низкая уверенность модели.
   Перекрытие руки и ракурс выглядят вероятным объяснением, но не установлены как
   единственная физическая причина. Порог видимости 0.5 не снижен.
2. Есть второй механизм потери измерений: при повороте резко сужается проекция
   плеч. Строгая нормализация отбрасывает кадр, если ширина относительно исходной
   становится меньше 1/2.5. Поэтому видимая на экране точка могла отсутствовать
   в данных анализа. Например, это происходит около 5.73–5.87 с первой попытки.
3. Прежний старт реагировал на скорость и удаление кисти от любой компактной
   исходной позиции. Направление вниз не исключалось. В отдельной синтетической
   проверке после правильной защиты опускание рук давало итоговый отчёт; теперь
   такого отчёта нет. Это проверка логики, не измерение техники человека.
4. Поиск максимального удаления в общем временном окне мог захватывать позднее
   опускание руки. Поэтому границы надо определять до оценки, а не выбирать
   момент, которому проще поставить балл.

## Что изменено

- Для джеба добавлен отдельный `JabCapture` под существующей обёрткой одной
  попытки. Он требует защиты перед стартом, подтверждает движение одной руки
  с увеличением её удаления от плеча, исключает преимущественно вертикальное
  опускание и одновременное поднятие обеих рук. Подготовка возвращает ожидание
  защиты, а не выдаёт результат.
- Если одна рука начала подниматься раньше другой и уже возник кандидат, полное
  поднятие обеих рук отменяет его с сообщением «отдельный джеб не выделен».
  Балла, прогресса и запроса к AI нет. Это не выполнение управляющего жеста внутри
  удара: countdown или повтор автоматически не запускаются.
- Видимость свободной руки не обрывает границы движения ударной руки. Однако
  исходные пропуски сохраняются и поступают в неизменённый анализ качества:
  недостаточно данных — нет балла и запроса к AI.
- Если позднее движение второй руки заставляет оценщик выбрать не ту руку,
  которую отслеживал захват, попытка отмечается неоднозначной и не получает балл.
  Исходные метрики оценщика не подменяются.
- Только поиск границ допускает сужение проекции плеч при сохранении исходного
  масштаба. Для оценки нормализация остаётся строгой. Потерянные точки не
  восстанавливаются и не дорисовываются как достоверные.
- Попытка закрывается на первом подтверждённом возврате. При плавном замедлении
  сохраняется устойчивый конец окна; последующее опускание не становится новым
  пиком. Критическая потеря отслеживания, несколько людей и тайм-аут отмечаются
  отдельно. После результата нужен новый пользовательский запуск.
- В результате есть локальные временные границы и причина завершения. Интерфейс
  показывает, выделена ли попытка и почему оценка недоступна, без повторяющихся
  одинаковых сообщений. Эти дополнительные данные не отправляются в NVIDIA.
- Джеб, начатый в конце 8-секундного ожидания, получает ограниченное время на
  завершение. Интерфейс не должен выдавать «удар не обнаружен» посреди уже
  подтверждённого движения.
- Личные видео в `testingdataset/` добавлены в исключения Git. Они не удалены,
  не изменены и не включаются в публикацию.

## Проверка на записях

| Проверка | Результат |
|---|---:|
| Размеченные намеренные попытки джеба | 14 |
| Пик захвата сопоставлен с ручным интервалом | 14 |
| Подтверждён возврат ударной руки | 13 |
| Прервано из-за неоднозначного числа людей | 1 |
| Достаточно данных для прежней системы оценки | 3 |
| Оценка обоснованно не выдана | 11 |
| Лишние выходы между джебами в тесте с автовзведением | 0 |

Остановка оставшейся попытки происходит около 61.5 с: модель вернула две позы.
Проверка одного человека намеренно не отключалась ради лучшего результата.

На трёх отрицательных записях (`handup`, `handcross`, `freemotions`) выходов
захвата нет. Восемь дополнительных старых клипов завершаются в пределах реально
наблюдавшихся кадров, три старых клипа без удара не дают попыток. Другие старые
клипы без достаточной начальной защиты или конца движения не считаются успешными;
искусственные начальные/конечные позы не добавлялись.

Синтетические проверки включают другую стойку и неправильную руку. Неправильная
рука по-прежнему диагностируется ядром, а не превращается в «нет удара».

## Чего эти числа не означают

- Это не 100% точность распознавания джеба и не подтверждение правильной техники.
  Новые записи использованы для разработки. Разметка намерений выполнена по
  видео с точностью примерно ±0.2 с и не заверена тренером.
- Окно возврата включает сглаживание и подтверждение: завершение обычно позже
  визуального возврата на доли секунды. `peak_ms` — максимум наблюдаемого движения,
  а не точно измеренный биомеханический момент.
- Прогон сохранённых точек обходит жест запуска и UI-проверку расстояния.
  Требования камеры перед оценкой не ослаблены. На слишком далёком ракурсе
  интерфейс может по-прежнему попросить подойти ближе.
- Скелет может продолжать терять недостаточно уверенные точки. Изменение делает
  захват устойчивее, но не превращает неуверенный результат модели в достоверный.
- Это режим одного джеба на уровне головы, не серий и ударов вниз/по корпусу.
  Одно намеренное поднятие руки с похожей траекторией всё ещё может быть
  неотличимо от попытки по одной камере. Нужен отдельный набор таких негативов.
- При 10 FPS быстрые движения всё ещё могут пропускаться. Прореживание имеющихся
  точек проверяет обработку времени, а не качество модели на медленном устройстве.

## Воспроизведение

Финальная локальная проверка: 179 тестов логики, 21 браузерный сценарий,
142/142 совпадения с Python при допуске 1e-7. Проверка типов, сборка и аудит
публикуемых файлов проходят. Реальная камера и внешний AI здесь не проверялись.

Из корня репозитория:

```sh
npm test
npm run test:parity
npm run build
npx playwright test
node --import tsx scripts/check-jab-recordings.ts private-data/testingdataset-2026-09-30 /tmp/jab-replay-new.json
```

Последний файл должен быть новым. Скрипт сохраняет хеши используемых точек,
разметки, захвата, анализа, оценки и конфигурации. Исходный baseline не меняется.
Собранные диагностические результаты находятся локально в
`private-data/jab-capture-2026-09-30/` и не входят в Git или сайт.

Следующая проверка — новые, ранее не использованные короткие записи: обычный
джеб, только подготовка, только опускание, намеренное поднятие одной руки,
неполный возврат и частичное перекрытие свободной руки. После независимой проверки
границ можно переходить к метрикам ошибок техники и только затем к баллам.
